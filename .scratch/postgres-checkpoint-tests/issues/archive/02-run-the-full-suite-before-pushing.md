# 02 — The definition of done documents a command that skips the Postgres suite

Status: completed
Type: task

## Context

> *This was generated by AI during triage.*

Filed 2026-09-08 out of the triage of
[01](01-postgres-checkpoint-tests-call-a-stale-arun-campaign.md), which found
three tests broken for two days without anyone noticing.

`CLAUDE.md:113` defines a task as done when:

> `uv run ruff check .`, `uv run ruff format`, `uv run mypy src`, and
> `uv run pytest` all pass.

`uv run pytest` **skips the entire Postgres suite** — everything in
`test_postgres.py` is marked `slow` and skips unless
`MARKETING_OS_TEST_POSTGRES=1` is set. The fast run reports 575 passed /
84 skipped and stays green with the durability tests broken.

So the documented definition of done is exactly what let 01 rot. Following the
rules to the letter produces a green result and a broken suite.

## Decision: no CI, manual gates before pushing

**Maintainer, 2026-09-08.** This is still an MVP, not a production product —
speed over correctness ceremony. No GitHub Actions workflow for the Python
suites. Instead the full suite is run manually before pushing code.

Context that informed it: `.github/workflows/` holds one workflow,
`contract.yml`, path-filtered to `contracts/**`. Nothing in `agent-harness/`
runs in CI today — not `pytest`, not `ruff`, not `mypy`. That stays true on
purpose.

The tooling for this already exists and needs no change:

- `make check` — ruff, ruff format, mypy, pytest (fast).
- `make test-postgres` — `MARKETING_OS_TEST_POSTGRES=1 uv run pytest -q`, the
  whole suite including the durable ones. Starts its own throwaway container via
  testcontainers, so it needs Docker but no setup.

What is missing is that the docs point at bare `uv run pytest` rather than at
these targets, so the habit has nothing to anchor to.

## What's needed

Documentation only. No code, no workflow file.

- Rewrite item 2 of **Definition of done** in `CLAUDE.md` to require the make
  targets rather than the bare commands, and to make explicit that
  `make test-postgres` (Docker required) is the one that actually covers
  durability. Say plainly that a green `uv run pytest` is not sufficient because
  the Postgres suite skips silently.
- Add the same expectation to the **Session ritual** / end-of-work part of the
  workflow router in `CLAUDE.md`: run the full suite before pushing.
- Fix the comment at `agent-harness/Makefile:14-15`, which reads "Use this in
  CI." There is no CI and there deliberately will not be one; it should say this
  is the pre-push gate.
- Check `agent-harness/README.md:163`, which documents `uv run pytest` with the
  note "offline; scripted fake chat model + fake reviewer (no network)". That is
  accurate as far as it goes, but should mention the Postgres suite is excluded
  and name `make test-postgres`.

## Out of scope

- Any `.github/workflows/` file for the Python suites. Explicitly rejected above.
- A git pre-push hook. Not asked for; the decision was a documented habit, not
  enforcement. Worth revisiting only if the habit demonstrably fails.
